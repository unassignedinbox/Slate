# Theraphosid — Cave Encounter

A real-time, fully procedural 3D tarantula (Theraphosidae) built in **Three.js**
(WebGL2), rigged and animated with a from-scratch inverse-kinematics gait
system, capable of walking on floors, walls and ceilings, with a
threat-display and strike-attack sequence, inside a hand-tuned procedural
cavern. No external model/texture assets — the creature, its fur, and every
cave surface are generated in code so the whole thing runs standalone.

## Run it

```bash
npm install
npm run dev      # http://localhost:5173
```

`npm run build` produces a static `dist/` you can host anywhere (no server
logic — everything is client-side WebGL).

## Controls

| Input | Action |
|---|---|
| `W A S D` / Arrow keys | Walk & steer |
| `Shift` | Skitter (fast gait) |
| `Space` | Threat display (rear up, bare fangs) |
| `F` | Strike attack (lunge + fang stab) |
| `C` | Cycle camera: Follow → Free Orbit → Cinematic |
| `T` / "Auto Wall-Walk Tour" button | Autopilot tour across floor → wall → ceiling → wall → floor |
| Drag / wheel (Free Orbit mode) | Orbit & zoom |

## What's actually modeled

- **Anatomy**: prosoma + opisthosoma (+ pedicel), 8 walking legs each with the
  full 7-segment arachnid leg (coxa, trochanter, femur, patella, tibia,
  metatarsus, tarsus + claws), 2 pedipalps, chelicerae with hinged
  orthognath (downward-striking) fangs, 8 eyes on an ocular tubercle, and
  spinnerets. Proportions and per-leg-pair splay/length come from published
  leg-segment ratios (see **Research notes** below).
- **Gait**: a true *alternating tetrapod* gait — legs {L1, L3, R2, R4} and
  {R1, R3, L2, L4} step as two out-of-phase quadrupeds, matching the
  biomechanics literature on spider locomotion (not a hand-waved "4 legs
  move at once" approximation).
- **IK**: each leg is solved with a plane-constrained FABRIK chain — the
  bend plane is built every frame from the hip→target direction and the
  body's current up axis, so the "knee" always bends the anatomically
  correct way (outward/away from whatever surface it's standing on),
  including mid-transition between floor/wall/ceiling.
- **Wall/ceiling walking**: the body's position and orientation continuously
  re-align to the nearest cave surface via raycasting (not a scripted rail);
  legs raycast independently for their own foothold, so the spider can
  genuinely walk up a wall and across a ceiling under either manual control
  or the autopilot tour.
- **Fur**: tens of thousands of individually-oriented instanced setae grown
  directly on the body/leg surfaces (via `MeshSurfaceSampler`), combed and
  length-varied per body region, including a distinct dorsal urticating-hair
  patch on the abdomen (a real New-World-tarantula defensive feature).
- **Coloration**: a "Mexican redknee" (*Brachypelma hamorii*)-style pattern —
  black body, burnt-orange patella/tibia bands, pale carapace guard hairs —
  chosen because it's both a real, documented pattern and reads clearly at
  a glance.
- **Attack animations**: a *threat display* (deimatic rearing posture with
  raised forelegs/pedipalps and bared fangs) that can escalate into a
  *strike* (explosive forward lunge + fang stab + recoil), matching how
  these behaviors are actually sequenced in the animal.
- **Cave**: one continuous, noise-displaced cavern (not floor+wall props)
  so locomotion across surfaces is physically continuous, plus stalactites,
  stalagmites, boulders, floor scatter, a silk-lined lair alcove, drifting
  dust, and bioluminescent-fungus point lights for atmosphere.

## Performance

The cave shell is ~70k triangles and every leg/body raycast runs every
frame, so the cave geometry is BVH-accelerated with `three-mesh-bvh`
(`computeBoundsTree` + `acceleratedRaycast`) — without it, raycasting alone
would be the framerate bottleneck.

## Verification

There's no headless browser available in this environment, so alongside
manual code review, `scripts/smoke_test.mjs` boots the entire simulation
(cave + spider + IK + gait + threat/strike + autopilot + camera) headlessly
under `jsdom` for thousands of frames and asserts no exceptions/NaNs — a
correctness net for the animation/math layer, though it can't verify pixels.
Please sanity-check the live visuals yourself; if anything reads as visually
"off," flag it and it can be iterated on quickly since every asset is
generated by code (no baked assets to re-author).

## Research notes (used to drive the proportions/behavior)

- Leg segmentation (coxa → trochanter → femur → patella → tibia →
  metatarsus → tarsus) and hydraulic (not muscular) leg extension.
- Alternating-tetrapod gait: Biancardi et al. 2011, *J. Exp. Biol.* 214,
  "Biomechanics of octopedal locomotion... *Grammostola mollicoma*"; also
  Wilson 1967, Ward & Humphreys 1981.
- Deimatic threat display (rearing, raised forelegs/pedipalps, bared
  fangs) and orthognath downward-striking fang mechanics of Mygalomorphae.
- Mexican redknee tarantula (*Brachypelma hamorii*) coloration and New
  World urticating-hair defense.

## Known limitations / honest caveats

This is a real-time procedural WebGL creature + environment, not a
DCC-sculpted/baked AAA game asset (no ZBrush sculpt, no baked normal maps
from high-poly, no mocap). Everything is generated from primitives, noise,
and math. It's built to be anatomically and behaviorally accurate and to
hold up under real-time scrutiny, but if your bar is literally
"shipped-AAA-studio asset," the next steps would be: hand-sculpted high-poly
→ baked normal/AO maps, a real strand-based hair system, and hand-keyed
animation on top of this IK layer.
